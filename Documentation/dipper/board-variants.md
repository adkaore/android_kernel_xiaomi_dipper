# Downstream board coverage audit

The pinned 4.9.337 source contains **15 root DTS files**, not 15 independently
verified physical boards. Its Makefile selects 12 standalone DTBs, or two P0
plugins when CONFIG_BUILD_ARM64_DT_OVERLAY is enabled. The revision-1 P0 DTS
exists but is not a listed build target. No owner's phone was inspected.

`legacy-resolved-boards.json` is generated by preprocessing and compiling all
15 roots at the exact recorded commit. Unlike the earlier source-only inventory,
it contains inherited SoC IDs and **final** reserved-memory ranges. Reproduce it
with the dtschema Python, a pinned clang and a built kernel dtc:

    /home/adkaore/android/toolchains/dtschema-venv/bin/python tools/dipper/audit-legacy-boards.py --output-dir /home/adkaore/android/work/legacy-board-audit --clang /home/adkaore/android/toolchains/clang-r596125/bin/clang --dtc /home/adkaore/android/out/dipper-core/scripts/dtc/dtc

Compare the generated JSON with the tracked manifest. Compiler warnings stay in
the external output directory. Old plugins are compiled with external fixups;
this audit does not claim to have applied them to a legacy or modern base.

## What the inherited source actually says

- P0, P1 CN, P1.1, P2 and MP have identical raw non-identity properties when
  compared **within the same SoC revision**. P1 GB additionally disables the
  controller at 0x890000 (modern label spi4). Generated phandles and root identity
  are excluded; phandle-valued properties are not otherwise normalized.
- v2 and v2.1 are distinct SoC selections. v2.1 also includes the dipper-specific
  audio overlay. This is not evidence that their entire hardware configuration
  is interchangeable, nor permission to copy old clock/IOMMU workarounds blindly.
- All 13 standalone definitions have the same 19 final fixed memory ranges.
  The board-level removed_region override ends at 0x8a900000, beyond the generic
  SDM845 TZ carveout. Splash, ramdump and ramoops also survive final inheritance.

## Memory regression correction

The first MP-only adaptation preserved selected generic/DSP ranges but omitted
part of the secure-memory board override and the three framebuffer/log regions.
The new compiled-DTB regression test failed on all four omissions before the
fix. It now checks interval coverage and no-map for **every** final fixed region,
as well as overlap and exact ramoops sub-buffer properties. Merely checking DTS
node names or the generic sdm845.dtsi constants would not catch this regression.

The new TZ node plus inherited AOP/cmd-db/SMEM cover the old removed_region
without overlapping each other. Splash remains reserved, not a live framebuffer.
Ramoops constants come from the pinned old board, not someone else's runtime
device dump. Runtime preservation across bootloaders/reboots is still untested.
